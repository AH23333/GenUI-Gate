## 5. 关键技术决策记录（KAN）

| # | 决策 | 理由 | 影响 |
|---|---|---|---|
| KAN-001 | sha256 用**同步纯 TS 实现**，不用 Web Crypto（`crypto.subtle.digest` 是异步） | Gate 管线是同步纯函数（v2 §6.3），异步哈希会污染整个 API；纯 TS 实现保证浏览器/Node 行为一致 | 多 ~2KB 代码；测试中与 `node:crypto` 交叉验证对冲实现错误风险 |
| KAN-002 | **ESM-only**（`"type": "module"`），CJS 双发布推迟到发布期（tsdown） | 开发期 ESM 足够；v2 §16 的双发布是发布要求不是开发要求 | 若下游需要 CJS 再引入构建器 |
| KAN-003 | `moduleResolution: "bundler"` + vitest 跑测试 + `tsc --noEmit` 做类型检查 | 免去 NodeNext 的 `.js` 后缀负担；发布时再切换输出策略 | — |
| KAN-004 | `.gitattributes` 强制 LF（含 fixture） | CRLF 污染会破坏跨平台哈希确定性（v2 §15.1 的测试前提） | Windows 检出也是 LF；编辑器需配 LF |
| KAN-005 | ir/gate **零运行时依赖**进 ESLint/评审纪律，暂不引入 dependency-cruiser | CI 简单化；依赖规则靠 code review + 包内 `package.json` 无 dependencies 断言 | M1 后视规模引入自动化强制 |
| KAN-006 | brand 类型暂缓（`ComponentId = string` 等普通别名） | 0.x 期 API 会动，branding 过早增加迁移摩擦；1.0 前引入 | 类型安全性靠运行时校验 + 测试 |
| KAN-007 | canonical JSON 采用 JCS（RFC 8785）精简子集：键按 UTF-16 码元排序（`Array.prototype.sort` 默认序）、数字用 `String(n)`（含 `-0`→`"0"`）、拒绝 NaN/Infinity/undefined/循环引用/非普通对象（Date/Map 等）、深度上限 256 | 排序与数字序列化均为 ECMAScript 规范定义，跨引擎确定；深度上限是 DoS 防护 | 与 JCS 完全一致的仅限 UTF-16 BMP 键序；测试用黄金向量 + 属性测试锁定 |
| KAN-008 | 覆盖率统计排除 `index.ts`（桶文件）与 `types.ts`（纯类型文件） | 两类文件无运行时逻辑，计入只会稀释真实覆盖率 | 阈值（90/90/85/90）作用于逻辑代码 |
| KAN-009 | `isJsonValue` 与 `canonicalize` 均以**显式栈**遍历，路径级（path-scoped）循环检测，全局共享引用（DAG）合法 | 与 gate 的树遍历纪律一致；避免深嵌套栈溢出 | `structuredClone`/适配层产物天然满足 |
| KAN-010 | gate M0 verdict 语义：`aggregate` 取**最严格 action 胜出**（pass < transform < requireApproval < block），severity 仅记录不参与聚合；limits 违规一律 `critical + block`，node-count 超限即 fail-fast 停止遍历 | v2 §6.2 的二维裁决模型在 M0 只需 action 维度；fail-fast 防止超大树拖垮宿主帧预算 | transform/requireApproval 在 M1 policy 阶段接入 |
| KAN-011 | adapter-a2ui IR 映射：`child`→`slots.child`、`children` 数组→`slots.children`、模板 children（`{componentId, path}`）→`props.children` 原样保留 + path 记入 bindings；envelope 字段（accessibility/catalogId/metadata）留在 props；bindings 收集 = 递归扫描单键 `{"@path": string}` 对象（含嵌套 `@call` args），扫描预算 100k；建树用显式栈 enter/exit 任务 + onPath 集合做祖先环检测（DAG 共享引用合法、真环记 child-cycle issue + 占位符 exit 时压缩） | 多子/单子/模板三类容器语义不同必须分开映射；协议的动态语义（@path/@call）不丢信息地压平进 IR bindings 供 M1 policy 消费；显式栈与全仓树遍历纪律一致 | v2 §5.1 IRNode 的 slots 结构即为此设计；A2UISession.reset() 重放 = resync 路径（v2 §5.2） |
| KAN-012 | audit CLI 审计层策略：退出码 0=报告通过 / 1=用法或读文件错误 / 2=parse-error、零 surface 记录、或存活 surface 被 block（fail-closed）；**deleted surface 是合法协议结局，不参与 block**（contact_form v1.0 官方语料以 deleteSurface 收尾，按"无存活即 block"的旧口径会误伤全部完整生命周期语料）；a11y 基线 M0 只做事实统计（props.accessibility 元数据覆盖率），无 policy 判定；CLI 运行时 = tsx devDep + bin shim spawn `node --import <file://URL> main.ts`，无构建步骤；纯核心 `runCli(argv, io, version)` 依赖注入，main.ts 为 I/O glue 并入覆盖率排除（KAN-008 延伸） | 审计层退出码是工具约定不是 gate 语义，gate 保持 limits-only（KAN-010）；deleted 语义由官方语料实测驱动；注入式设计让 CLI 核心可 in-process 测试 | M1 policy 阶段接管判定类检查时，audit 层退出码口径需随 policy 配置化 |
| KAN-013 | bench 与 A8 装置：`pnpm bench` = 确定性构造 500 节点/深度 12 宽树（纯算术分布，无随机源、被测代码路径无时钟），A6 预算 p99 ≤ 5ms，退出 0/2；**A6 实测校准**（Windows / Node 24 / 2026-11-04）：p50 0.311 / p95 0.628 / p99 0.811 ms，余量 ~6×，全量校验方案确认无需优化（v2 §6.7 已删记忆表）；A8 = `packages/audit/test/consistency.test.ts` 对 53 官方语料锁定全管线摘要金标（inputSha256 / irHash / verdict / 计数，不落全报告），`UPDATE_GOLDENS=1` 再生成，CI 矩阵（ubuntu/windows × node 20/22）复验即跨平台装置；bench 暂不进 CI（TD-002 CI 未首跑，性能门禁待 CI 验证后挂） | v2 §6.6 预算全是 [假设，P0 校准点]，bench 是校准装置不是优化依据（§6.7：超预算先 profile）；A8 金标只存摘要级防止 diff 噪音 | CI 首跑后把 `pnpm bench` 挂进 CI（v2 §15.6）；A6 数字随平台/Node 版本浮动，CI 门禁若挂需按平台分别校准或加容差 |
| KAN-014 | 公开物料语言与 demo 选型：README/社区首发帖用**英文**（社区首发面向国际 A2UI 生态，a2ui.org/Discussions/Reddit 均英文），内部执行文档（进度/交接/踩坑/指南）保持中文；README 的 GIF 用 HTML 注释占位（录好取消注释），不放断链图片；主 demo 样例选 30_live-invitation-builder（20 组件全展开树、无模板压缩，报告数字直观），BLOCK demo 用深度 33 链（恰好 1 条违规，输出紧凑），不用 40 深链（8 条违规路径行刷屏）；官方 fixtures 计数以实测 53 为准（早期提交信息中 52 为笔误） | 公开仓库的目标读者 = 国际 A2UI 社区；README 里的数字（测试数/语料数/p99）是承诺，须与仓库实际一致 | 后续公开物料（M2 《GenUI 无障碍现状实测》）沿用英文；若项目起中文社区再考虑双语 README |
| KAN-015 | 审计文本渲染消毒策略：`renderText` 对一切**输入派生字符串**（surfaceId/catalogId/rule 样本/adapter issue 消息）经 `safeText()` 剥离全部 C0 控制字符 + DEL（`\x00-\x1F\x7F`）后再插值；`renderJson` 靠 `JSON.stringify` 的控制字符转义天然免疫，不做额外处理 | 深测探针实测：恶意 spec 可经 surfaceId 注入 ANSI 转义序列（改终端标题/清屏）或 `\r` 伪造报告行（"Overall: PASS"）——终端转义注入 + 报告伪造（PIT-008）；JSON 路径无此面 | 回归锁 = audit 属性测试 "renders hostile ids without leaking any control character"（EVIL 字符集含 `\x1b`/`\r`/`\n`/`\x00`/`\x07`/`\x7f`）；M1 session 预览、M2 报告等一切人类可读渲染沿用"输入派生字符串先消毒"纪律 |

## 7. 修改纪律（对会话中 AI 的硬性要求）

- **小步提交**：一个提交 = 一个可独立回滚的语义单元（feat/fix/docs/chore/test 分开）；
- 每个提交前：`pnpm test && pnpm typecheck` 全绿；
- 踩坑即录 `踩坑记录.md`，不攒批；
- 破坏性变更（公共 API/IR 结构）必须先在 `进度.md` 登记再做；
- 文档与代码同提交优先于"稍后补文档"。
