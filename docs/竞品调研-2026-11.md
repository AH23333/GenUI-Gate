## 一、调研方法与范围

## 三、重点产品详情

### 1. A2UI（Google 主导，Apache 2.0）

**版本进展**（相对构想v0 的关键变化）：
- v0.9.1（现行）：标准化 `application/a2ui+json` MIME 类型，放宽 surfaceId 约束；
- **v1.0（候选）**：新增客户端→服务端 RPC（`actionResponse`）、action IDs、`surfaceProperties` 重命名。协议仍在快速演进。

**A2UI over MCP 已落地**：构想v0 写作时为"Google 正在考虑"，现已是官方指南，含三种集成模式（A2UI over MCP / MCP Apps in A2UI / A2UI in MCP Apps）。

**生产部署**（官方 "A2UI in the World"）：
- Google Opal：数十万用户级 AI mini-app 平台，A2UI 核心贡献团队；
- Gemini Enterprise：企业自定义 Agent，用于数据录入表单、审批仪表盘、工作流（注：目前仅 A2A 路径注册的 self-serve agent 支持 A2UI 渲染，Vertex AI Agent Engine 托管路径暂不支持）；
- Flutter GenUI SDK：以 A2UI 为底层协议的服务端驱动 UI；
- Google ADK：开发 UI（ADK Web）原生渲染 A2UI。

**生态**：渲染器覆盖 Angular、Flutter、Lit、Markdown、Vue（社区）；官方 A2UI Composer（可视化生成 A2UI JSON）；Python agent SDK。

**官方对比定位**（a2ui.org "How Does A2UI Compare?"）：

| | A2UI | MCP Apps | AG-UI | ChatKit |
|---|---|---|---|---|
| 方法 | 声明式组件蓝图 | 预构建 HTML（`ui://`） | 高带宽传输协议 | 封闭组件层 |
| 渲染 | 原生组件 | 沙箱 iframe | 开发者自定义 | OpenAI 生态 |
| 样式 | 宿主控制 | 远端服务器控制 | 开发者控制 | OpenAI 控制 |
| LLM 生成 | 为流式输出设计 | 服务端预构建 | 经 A2UI 集成 | — |

### 2. Thesys（C1 API → OpenUI Cloud）

定位已从"Generative UI API"（C1）升级为**全栈商业平台**，三产品线：
- **OpenUI Cloud**（原 C1）：LLM 输出→生产级 UI（图表、表单、卡片、表格、仪表盘）；
- **Reports API**：对话/数据/文件→可分享、可导出（PDF/PPT）的报告类交付物；
- **Agent Builder**：无代码创建、部署、嵌入带 GenUI 的 Agent。

**治理相关卖点**（对本构想最重要的信号）：
- "Handles errors & corrections: Validate UI, fix bad outputs, and use fallbacks when models fail"；
- observability、模型 fallback；
- 合规：GDPR、SOC 2、ISO 27001 认证；零数据保留、私有化部署；
- 性能主张：比 JSON renderer 快 3 倍渲染、少 67% token（对应其 OpenUI 开源框架）；
- BYO 设计系统（组件、token、样式）。

**判断**：Thesys 是商业化最完整的玩家，但其治理能力是**平台内建封闭能力**，服务于自家渲染管线，不是可嵌入任意前端的独立治理层，也未覆盖 a11y gate、快照回滚、策略即代码。

### 3. AGenUI（高德 + 阿里千问，2026-05 开源）

- 行业首个覆盖 iOS、Android、HarmonyOS 三端的**原生 A2UI 渲染 SDK**；
- 云侧将用户意图沉淀为"可执行界面资产"，端侧原生渲染；
- **AGenUI Studio**：本地化、BYOK 的 A2UI 生成工作台（自然语言→可渲染界面）。

**判断**：渲染层在中国生态已被占据；"生成工作台"正成为标配（A2UI Composer、AGenUI Studio 佐证）。

### 4. CopilotKit / AG-UI

- CopilotKit 定位升级为 "The Enterprise-Ready Frontend Stack for Agents"，主打企业前端栈；
- AG-UI 为传输协议，与 A2UI day-zero 兼容（"AG-UI as the pipe, A2UI as the content"）；
- 仍以 React 为主，Vue/Angular 经 CopilotKit 间接支持。

### 5. json-render（已入 Vercel）

- json-render.dev，用 Zod schema 定义组件目录并渲染 A2UI catalog；
- 被收录为 A2UI 官方第三方集成。

**判断**：独立"声明式中间层"玩家在向大平台靠拢（Vercel），单纯组件目录/渲染层没有独立公司生存空间。

### 6. AG2 A2UIAgent

- 多 Agent 框架 AG2 的参考 Agent，**内置 schema 校验 + 自动重试**、A2A/AG-UI 双传输、自定义 catalog。

**判断**：又一个"校验被框架内建"的证据。

### 7. MCP Apps 与 ChatKit

- MCP Apps（SEP-1865）已 Final：`_meta.ui.resourceUri` 声明 UI 资源，沙箱 iframe 渲染，服务器控制体验；
- **OpenAI ChatKit 新入场**：封闭生态组件层。协议层从"Google 单极"走向 **A2UI（开放）/ MCP Apps（MCP 生态）/ ChatKit（OpenAI 封闭）三极分化**。

### 8. 构想v0 中提到但无法验证的产品

- **begeniux**：Bing/百度多轮检索无任何可检索的公开产品痕迹（无关结果约 50 条）；
- **Apex Trust Runtime**：GitHub 全站仓库搜索 0 结果，无独立官网被索引。

**结论**：两者要么 stealth、要么已消失、要么为私有内部项目。构想v0 中"信任治理已有产品验证（Apex）"的论据**不可靠**。治理空白依然成立——但需要重新审视其成因：是没人想到，还是做了活不下来。

## 四、结构性判断：治理能力正被各层吸收

| 治理能力 | 被吸收程度 | 吸收者 | 独立产品机会 |
|---|---|---|---|
| schema 校验、组件白名单 | **已被内建** | A2UI 协议（v0.9 起 `validation failed` 格式化）、AG2、AGenUI | 无 |
| 错误修正、fallback | **已被内建** | Thesys OpenUI Cloud、AG2 A2UIAgent | 无 |
| 生成工具链/工作台 | 已成标配 | A2UI Composer、AGenUI Studio | 无 |
| 可访问性硬 gate | **无人做** | —（各家宣传均未提及 a11y） | **有** |
| 快照/回滚（含组件状态） | 无人做 | — | 有 |
| 策略即代码（policy-as-code） | 无人做 | — | 有 |
| 布局质量评估基准 | 无人做 | —（"GenUI 界的 Lighthouse"空位） | 有，标准卡位价值高 |
| 跨协议中立治理 | 无人做 | — | 有，随三极分化增值 |
| 偏好学习闭环（个性化数据资产） | 无人做 | — | 有，数据壁垒型 |

**核心结论**：基础校验将在 6-12 个月内成为所有主流框架的免费内建能力，做这一层没有独立产品机会；真正的空白集中在**合规硬 gate、质量基准、回滚快照、策略即代码、跨协议中立**——且"跨协议中立"因 ChatKit 入场和 MCP Apps 定稿而比以往更有价值。

## 五、对构想的影响（→ 构想v1 的依据）

1. **协议押注 A2UI 被验证**：生态爆发（Google 全线产品采用 + 中国三端渲染开源），但协议仍 pre-1.0 快速演进，必须加防腐层；
2. **定位必须从"A2UI 之上"改为"协议无关"**：绑定单一协议的治理层会被协议内建能力吞掉；三极分化制造了"不管 UI 从哪来都要过同一道治理闸门"的需求；
3. **首个切口改为可访问性硬 gate**：唯一同时满足"无人做 + 法规强制（WCAG/欧盟 EAA 已生效）+ 技术可落地（catalog 级预审计 + 渲染期组合检查）"的能力；Thesys 的合规认证收入证明企业为合规付费，但无人做 a11y 合规；
4. **"个性化布局"叙事必须降维为"个性化信息编排"**：布局质量由人工模板保证，Agent 只做模板选择与槽位填充（依据构想v0 自己引用的"布局是 LLM 主导性弱点"结论）；
5. **护城河重排**：校验是获客手段；真正的护城河是偏好学习数据、审计证据链、质量基准的行业标准卡位；
6. **参照系修正**：Apex/begeniux 从竞品列表中移除；新增 ChatKit、AGenUI Studio、Thesys Reports API 为趋势参照。
