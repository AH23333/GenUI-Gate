# 产品设计 v3（开源版）：GenUI Gate —— 社区治理层

> 版本：v3（2026-11-03）｜ 性质：**非商业开源项目规划（执行用）**
> 基线：`产品设计v2-修订.md` —— 技术规格的**权威版本**，本档不重复其工程细节，只做范围裁剪与开源化改造；与本档冲突处以本档为准（仅限范围裁剪类冲突）。
> 声明：本版剥离 v2 全部商业化层（ICP/TAM、分发获客、定价、企业审计链、商业假设验证）。v2 的商业章节进入**休眠**状态而非废弃——若项目出现显著生态信号，v2 可作为商业化路线图重新启用（毕业条款见 §8）。

---

## 1. 项目性质与"试一下"要回答的三个问题

**定位**：A2UI 生态的社区治理工具——**GenUI 的 ESLint（开发期质量）+ Lighthouse（可分享报告）+ 运行时护栏（pending-inert / 回滚）**。

**非商业承诺**：Apache-2.0 单一许可；无付费版、无托管服务、无企业功能分支；不外传任何遥测（连云端聚合都不存在，本地即止）。

"试一下"要验证的三个命题（每个都有可观测信号与退出线，见 §8）：

1. **技术命题**：gate 管线在真实 A2UI 流上可用且开销可接受（继承 v2 假设 A6/A7/A8）；
2. **生态命题**：A2UI 社区是否认为治理层有独立价值（集成 PR / 社区反馈）；
3. **兴趣命题**：是否有外部开发者愿意使用与贡献。

## 3. 一句话定位（README 首屏）

> **GenUI Gate：给 Agent 生成的 UI 加一道质量与可访问性闸门。协议无关（先支持 A2UI），渲染前校验、修正、拦截，附带回滚与本地质量报告。**

对比定位（对外叙事纪律）：
- **不是**又一个 GenUI 渲染器（A2UI 生态渲染器、AGenUI 已占满该生态位）；
- **是**协议生态的质量配套层；
- 对外统一说"质量与可访问性"，**不说 EAA/合规**——法规驱动叙事（v2 §3）属于商业版，OSS 版背不起合规承诺（§9）。

## 4. License 与项目治理

- **Apache-2.0**。理由：A2UI 本身 Apache-2.0，生态兼容最大化；比 MIT 多专利授权层。
- **不选 AGPL**：治理工具需要被企业前端栈无顾虑采用，copyleft 会吓退目标用户。"不商用"是作者意愿而非许可强制——Apache-2.0 允许他人商用，这是**接受的代价**，也是生态位成立的条件（§10 风险表）。
- 治理：无 CLA，外部贡献走 DCO 签名；行为准则用 Contributor Covenant；RFC-lite：`docs/rfcs/` 编号提案，重大变更（IR 结构 / 规则 schema / 公共 API）先 RFC 后实现。
- 版本策略：semver；0.x 期包内一切可破坏；1.0 起承诺稳定的是 `gate()` / Session 公共 API + 规则 schema + IR 字段语义（只增不改）。

## 6. 里程碑（1–2 人兼职口径）

顺序刻意设计：**先 headless CLI，后框架集成**。audit CLI 是零框架依赖的最小可演示产物（README GIF 三天内可产出）；session/react 集成复杂度高一档，放在核心管线被验证之后。

### M0（第 1–2 周）：能跑的报告器

- ir + adapter-a2ui + gate（limits / schema 子集 / whitelist）；
- `genui-audit`：输入 spec 或 fixture 目录 → 终端报告（verdict 统计、规则命中、a11y 基线检查）+ `--json`；
- bench 脚本 + 跨平台哈希一致性测试（v2 A6/A8 的最小验证装置）；
- **出口**：仓库公开，README 含 GIF；对官方 samples（quickstart / restaurant_finder 等 10 个）能出报告；
- **此时刻即生态命题的第一探测点**：报告贴到 A2UI 社区（§7）。

### M1（第 3–5 周）：可嵌入的运行时闸门

- session + gate-react + pending-inert + spec 回滚 + policy 简化版（baseline a11y 包 + shadow）；
- proposer-example + demo app（官方 restaurant_finder 改造版）：提议 → Gate → 预览（inert 摘除）→ 确认 → 回滚全链路；
- 本地指标 devtools 面板（v2 §11.2 交互分类事件，本地呈现，零网络出口）；
- **出口**：闭环 demo 视频；M0 CLI 与运行时共用同一 gate（同一确定性测试覆盖）；失败矩阵黄金测试绿。

### M2（第 6–8 周）：生态接入

- catalog CLI（manifest lint + axe 审计）；
- 文档站（quickstart："5 分钟给 A2UI 加闸门"）+ playground 静态页（在线贴 spec 出报告，纯静态、无后端）；
- 向 a2ui-project 提交第三方集成 PR（对照 json-render 收录先例）；
- 《GenUI 无障碍现状实测》公开报告：audit CLI 对官方 samples + 公开 GenUI 语料跑 a11y 基线（≈2 人日，兼作 v2 §23.3-1 未核实数据的自校准）；
- **出口**：A2UI 集成列表收录，或获得社区明确反馈。

### M3+（弹性）：只做社区信号最强的一项

候选：Vue adapter / ChatKit adapter / 社区 baseline 规则包 / 状态快照（v2 §10 的 P2 决策证据此时才有数据基础）。**不预排 roadmap，M3 由 §8 信号决定。**

## 8. "试一下"的验证判据（替代 v2 §17 / §20 的 Go/No-Go）

| 命题 | 信号 | 阈值（solo 试验口径） | 无信号处置 |
|---|---|---|---|
| 技术：管线可用 | bench 达 v2 §6.6 预算或书面重校准；demo 全绿 | M1 出口时达成 | 纯技术不达 → 存档并发布复盘 |
| 生态：A2UI 社区认为有价值 | 集成 PR 收录 / Discussions 正面反馈 / star 增长 | M2 后 4 周内 ≥1 项 | 生态冷淡 → 转个人工具维护，不推 M3 |
| 兴趣：外部开发者参与 | 外部 issue / PR / "我试了"复现 | M2 后 8 周内 ≥3 个独立外部互动 | 零互动 → 归档（archive），仓库保留作复盘素材 |
| Agent 编排质量可学习（v2 A3） | demo 中回滚率随使用下降 | **仅诊断，不作判据**（无试点流量） | N/A——商业版专属命题，OSS 版无数据基础 |

**毕业条款**：若生态 + 兴趣信号显著（被 A2UI 官方推荐 / 出现主动贡献者 / 有团队询问生产使用），回头评估是否启用 v2 商业路线（ICP / 定价 / 审计链章节届时重新生效）。该决策不在本档承诺范围内——"试一下"的默认结局是其中一种：继续开源维护、转个人工具、或归档，三者都是合理收尾。

## 9. 明确不做（非商业承诺清单）

- 无付费版、无托管服务、无审计链 / audit-server、无签名策略分发；
- 无遥测外传——本地文件导出即止，不提供任何远端导出端点；
- 不承诺 SLA 与支持，issue 尽力而为；
- 不做 EAA / 合规对外叙事（避免无商业化支撑却背合规承诺，见 §3）；
- 不做商标 / 品牌防御性注册（不商用的自然结果）。

## 10. 风险（OSS 版特有）

| 风险 | 缓解 |
|---|---|
| solo 维护者倦怠（v2 §15 测试矩阵对 1 人偏重） | M0/M1 只保留性质测试 + 黄金测试 + 最小混沌注入；CI 全绿优先于覆盖数字；M2 起用 good-first-issue 招募贡献者 |
| A2UI 协议漂移（v2 A11，pre-1.0 高速演进期） | 防腐层 + adapter 一致性套件 + 订阅 release——继承自 v2 的最大外部依赖风险，M0 的 fixture 全部取自官方 samples 以保持同步压力 |
| 无商业激励下兴趣衰减 | 里程碑短（2–3 周一个）、每个 M 有可演示产物、§8 给出明确退出线——"试一下"允许失败，失败也有复盘资产 |
| 他人拿去商用（Apache-2.0 允许） | 接受。工具可被自由采用是生态位成立的条件；若发生，说明方向被验证，且 v2 商业路线图的判断获得外部背书 |
