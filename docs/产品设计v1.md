# 产品设计 v1：GenUI Gate —— 生产级治理层

> 版本：v1（2026-11）｜ 上游：`构想v1.md`、`竞品调研-2026-11.md`
> 工作名 **GenUI Gate**，包前缀 `@genui/*`。本文档是工程设计文档，目标是可直接开工的生产级规格：每个模块给出契约、预算、失败模式与验证方式。

---

## 0. "生产级"的验收定义

本文所有设计围绕五条硬约束，任何后续决策与之冲突时以约束为准：

1. **确定性优先**：Gate 核心是纯函数、跨平台确定性（同输入 → 同输出与同 trace 哈希）。这是服务端复算审计、策略回归测试、可复现故障诊断的共同前提。
2. **预算先行**：每个模块在进入开发前先定延迟/内存/体积预算，预算进 CI（见 §11、§12）。
3. **信任边界显式化**：Agent 输出按不可信处理；catalog 与 policy 是可信输入（企业版带签名）；用户动作可信；宿主应用可信。
4. **降级优于失败**：任何子模块故障不允许白屏或崩溃宿主，只允许降级到 fallback/降级路径，且降级必须可观测（§11 失败矩阵）。
5. **隐私默认**：遥测本地优先、内容零外传（仅形状指纹），opt-out 全局生效（§8）。

## 1. 总体架构与依赖规则

```
┌────────────────────────────────────────────────────────────┐
│ 宿主应用 (React / Vue / 原生)                                │
│   └─ @genui/gate-react 等（薄集成，只依赖 Session API）        │
├────────────────────────────────────────────────────────────┤
│ Session 层（有状态编排）                                      │
│   ingest → arbitrate → stage/commit 事务 → snapshot → telemetry│
├────────────────────────────────────────────────────────────┤
│ Gate 核心（纯函数、零依赖、零 I/O）                            │
│   limits → schema/whitelist → policy → a11y → budget → fix  │
├────────────────────────────────────────────────────────────┤
│ IR 层：归一化 + 防腐（@genui/ir）                             │
├────────────────────────────────────────────────────────────┤
│ Adapters：a2ui / mcp-apps / chatkit（可替换）                 │
└────────────────────────────────────────────────────────────┘
   Ports（注入，不由核心实现）：Clock / Storage / Logger / Sink
```

**依赖规则**（CI 强制）：
- 核心三包 `ir` / `gate` / `policy` 零运行时依赖、无 DOM/Node API，浏览器与 Node 双端可运行（服务端复算依赖此点）；
- 平台差异只经 Port 接口注入（时钟、存储、日志、导出 sink）；
- 框架集成包只依赖 Session API，不触碰核心内部结构。

## 2. IR：内部表示与流式语义

### 2.1 节点模型

```ts
interface IRNode {
  id: NodeId;                 // adapter 分配，会话内稳定
  type: ComponentId;          // 对应 catalog 条目；未注册类型 = 白名单外
  props: JsonValue;           // 已过 props schema 的规范化值
  slots: Record<string, IRNode[]>;  // 命名槽位。IR 不含任何空间坐标
  bindings?: BindingRef[];    // 数据绑定，只能引用宿主注册的数据源
  capabilities: Capability[]; // 该节点声明的能力需求（如 needsNetwork）
}
```

**设计决策：IR 没有布局字段。** 空间排列由人工布局模板（catalog 一等公民）持有，Agent 只能选模板、填槽位。这是"个性化信息编排，而非个性化布局"在数据结构层面的落实——LLM 布局弱区在 IR 层面就无法表达。

### 2.2 流式与提交帧

- Adapter 将协议流翻译为**操作序列**（upsertNode / patchProps / deleteNode），IR 以不可变树 + 结构共享方式应用，支持 A2UI 的增量流式渲染；
- 操作按 **commit frame**（协议层消息边界）分组。Gate 只在 commit frame 边界做完整校验；帧内增量渲染仅做 `limits` 快速检查（防流式期间 DoS），正式 Verdict 以帧边界为准；
- 背压：会话内帧队列上限 100。溢出策略 = 丢弃最旧未处理帧 + 请求 adapter 全量重同步（A2UI `createSurface` 重放；要求所有 adapter 必须实现 resync 协议，这写进 adapter 一致性套件）。

### 2.3 规范化与哈希（审计基石）

- **Canonical JSON**：键排序、UTF-8、无空白差异 → sha256 得 `specHash`。哈希前必须规范化，杜绝"解析器差异导致客户端与服务端对同一 spec 算出不同哈希"的审计漏洞；
- IR 解析不用深度合并：原始 JSON 经显式构造器逐字段复制（reviver 白名单），阻断原型污染与多余字段透传；
- 未知字段：**保留但 Gate 忽略**（前向兼容）；未知组件类型：**白名单规则直接 block**（安全优先于兼容）。

### 2.4 版本

`irVersion` 字段 + 逐版本迁移函数；迁移函数与 Gate 同样要求纯函数。审计记录同时落 `{irVersion, engineVersion, policyHash, catalogHash}` 四元组（§9）。

## 3. Gate 核心：管线、Verdict 与性能

### 3.1 管线（顺序固定，每级短路规则明确）

```
1. limits      硬上限检查（DoS 防线，fail-closed，超限 → quarantine）
2. schema      props 对 catalog manifest 的 JSON Schema 校验
3. whitelist   组件/能力/区域 白名单（含 zone 越权）
4. policy      策略引擎（§4）
5. a11y        组合级检查（标题层级/landmark/焦点顺序）
6. budget      性能与内容预算（节点数/文本长度/列表长度）
7. fix         具名修复器串行应用（fix 之间有依赖序，编译期定序）
```

### 3.2 Verdict：severity × action 二维模型

单值 pass/transform/block 不足以表达生产语义，改为二维：

| | pass | transform | requireApproval | block |
|---|---|---|---|---|
| info | ✅ | — | — | — |
| warn | ✅（记录） | ✅ 自动修 + UI 轻标注 | 可选 | — |
| error | — | ✅ 自动修（可撤销） | ✅ | ✅ + fallback |
| critical | — | — | — | ✅ + fallback + 隔离 |

规则定义 severity 与默认 action 的合法组合；违反组合（如 critical+transform）在策略编译期报错，而不是运行时静默容错。

### 3.3 核心契约（纯函数 + effects 分离）

```ts
interface GateResult {
  ir: IR;                    // 可能经 fix 修正后的树
  verdict: Verdict;          // 最严格 action 胜出
  trace: TraceEntry[];       // 每条命中：ruleId/severity/action/nodePath/before/after
  effects: Effect[];         // 延迟副作用（遥测、快照提示）——由 Session 执行
}
gate(ir: IR, ctx: GateContext): GateResult;
```

Gate 自身**不执行**遥测、不落快照、不调时钟——副作用以 Effect 值返回，由 Session 统一执行。这保证 gate 可在 Node 服务端无副作用复算（§9 双跑验证）。

**确定性纪律**（进 code review checklist）：
- 核心禁用 `Date.now()` / `Math.random()` / locale 相关比较；
- 时间相关策略经 `ctx.evaluationTime`（由 Session 注入）求值；
- 集合遍历使用稳定序（插入序或 ID 序）。

### 3.4 增量校验

- 子树哈希 + LRU 记忆表（上限 500 条）：未变化子树跳过 2–6 级重验，只重算受 patch 影响的路径；
- fix 修正会使下游子树哈希失效，失效传播沿修改路径精确计算，不做全树失效；
- 记忆表 miss 或溢出时退化为全量校验——正确性不依赖记忆表。

### 3.5 DoS 硬上限（limits 级，全部 fail-closed → quarantine）

| 限制项 | 上限 | 说明 |
|---|---|---|
| 树深度 | 32 | 防栈溢出（配合显式栈遍历，不用递归） |
| 节点总数 | 2,000 | 超限隔离，请求 agent 重发精简版 |
| 单节点子节点数 | 64 | |
| 单 prop 大小 | 16 KB | 文本类 prop 另受 budget 级约束 |
| 单帧总大小 | 256 KB | |
| fix 链应用次数 | 单帧 ≤ 50 次 | 防修复器振荡，超次降级为 block |

### 3.6 性能预算（CI bench 门禁）

| 指标 | 预算 |
|---|---|
| gate 全管线 p99 @500 节点/深度 12 | ≤ 5 ms |
| Session 帧摄入 p99 | ≤ 10 ms |
| 核心三包体积（gz 合计） | ≤ 40 KB（目标 30） |
| 会话常驻内存上限 | ≤ 10 MB |

### 3.7 Gate 自身故障：GateGuard

Gate 抛出任何异常 → GateGuard 捕获 → fail-closed 渲染 fallback + quarantined spec 完整落盘（经 telemetry 通道，默认不含用户数据）→ 宿主不感知异常。**Gate 永远不允许崩溃宿主应用。**

## 4. 策略系统

### 4.1 分层与合并语义

```
baseline（随包发布，WCAG/EAA 基线）
  < org（企业下发，可签名）
  < app（宿主应用仓库内，走代码评审）
  < runtime（运行时实验开关，仅能收窄）
```

**合并规则（编译期，非运行时）**：
- 单调收紧：高层只允许比低层更严，尝试放宽低层 fail-closed 规则 → **编译错误**（带规则 ID），不允许静默覆盖；
- 同层规则冲突 → 编译错误；
- 编译产物 = 索引化谓词表（按组件类型分桶），Session 创建时编译一次，渲染期零解析开销。

### 4.2 规则模型：数据，不是代码

```yaml
- id: table-requires-caption
  match: { component: Table, props: { caption: absent } }
  check: derivesFromDataSchema
  severity: warn
  action: transform
  fixer: captionFromSchema     # 具名修复器，内置实现，非任意代码
  zone: any
  message: "表格缺少可访问名称，已从数据字段推导补齐"
- id: password-field-zone
  match: { component: PasswordInput }
  check: inZone                # 敏感组件只允许出现在注册的安全区
  severity: critical
  action: block
  zone: [secureForm]           # 安全区在应用构建期注册，Agent 不可写
```

- **match 是数据**，check/fixer 是**内置具名谓词/修复器**——策略文档永远不可执行任意代码，阻断"策略即攻击面"；企业自定义谓词走 WASM 沙箱（P3，暂缓）；
- 规则内禁止正则；确需模式匹配的内置谓词使用有界匹配（编译期校验长度上限），防 ReDoS。

### 4.3 执行灰度：Enforcement Ratchet

每条规则可配 `mode: off | shadow | transform | block`，叠加按 `userIdHash % 100 < cohort` 的队列分片：

- **shadow**：只记录本应触发的 verdict，不影响渲染——上线任何新规则必须先过 shadow 期（默认 ≥ 7 天或 ≥ 10k 帧）；
- 灰度只允许手动收紧（ratchet），**不允许在无人值守下自动从 shadow 升到 block**；
- shadow 数据用于计算"预估拦截率"，超过阈值的规则要求人工评审后再收紧——这是"a11y gate 误拦率高导致弃用"风险的系统性解法。

### 4.4 策略测试

- 策略单测：规则 × 样例 spec 的期望 verdict 矩阵；
- **策略回归**：CI 内用录制语料库（§12）回放新旧两版策略，diff verdict digest——任何非预期的收紧/放宽都会挡在合并前；
- 企业签名策略包：版本固定、禁止降级（防回滚攻击）。

## 5. Catalog：组件清单与审计流水线

### 5.1 Manifest 契约

```ts
interface ComponentManifest {
  id: ComponentId; version: string;
  propsSchema: JsonSchema;            // schema 校验依据
  a11yContract: {                     // 预审计依据
    role: string; requiredLabels: string[];
    contrastClass: 'aa' | 'aaa';      // 对比度在入库时按 token 组合审计
    focusable: boolean;
  };
  perfClass: 'light' | 'medium' | 'heavy';   // budget 级组合预算的依据
  allowedZones: ZoneId[];             // 缺省 any；敏感组件必须显式声明
  stateSerializer?: SerializerId;     // 参与快照（§7）
  capabilities: Capability[];         // 声明式能力需求
}
```

### 5.2 审计流水线与生命周期

- **入库审计**（CI 任务）：对 manifest + 参考实现跑 `@genui/audit`——对比度（按设计 token 组合枚举）、语义标签、键盘可达。产出审计报告，报告哈希随 manifest 存储；
- **catalog bundle** = manifests + 审计证明，版本 = 内容哈希；企业版可远程下发 + 本地 pin（离线可用）；
- 生命周期：`draft → audited → deprecated（策略阻止新引用，存量渲染不受影响）→ removed`。组件级 a11y 缺陷在入库时拦截，从源头阻断"缺陷进入设计系统后组织级传播"；
- **a11y 检查的双层边界**（明确划界，防过度承诺）：入库审计 + IR 组合检查都是**静态分析**；依赖真实渲染结果的项（动态背景对比度、实际重叠）不在 Gate 能力内，见 §15 开放问题。

## 6. 仲裁与应用事务

### 6.1 提案状态机（单写者语义）

```
proposal ──stage──► staged(preview) ──commit──► applied ──► locked | reverted | superseded
   ▲                     │ abort                     │
   └─────────────────────┴───────────────────────────┘（新提案可重新进入）
```

- 同一 zone 同时只允许一个 staged 提案：新提案到达 → 旧提案 aborted（或按策略排队），写冲突在状态机层面消除；
- **两阶段提交**统一了"预览-确认"与"快照"：stage 时完成 Gate 校验并生成 IR' + diff，commit 时落快照并应用。预览与最终渲染走完全相同的代码路径，杜绝"预览和上线不一致"。

### 6.2 优先级仲裁（固定求值序，结果进 trace）

```
用户锁定（zone 级硬停） > 用户偏好 > 平台策略（zones/预算） > Agent 提议
```

确认策略由 policy 决定：`user-confirm`（MVP 默认）/ `auto`（低风险白名单变更）/ `never`。仲裁全程确定性——"为什么这样展示"直接由 trace（规则 ID + 输入路径 + 结论）渲染，**禁止 LLM 生成解释**。

## 7. 快照与回滚

| 设计点 | 决策 |
|---|---|
| 快照点 | 仅 commit 边界（离散事件），不做每帧快照 |
| 内容 | `{ irHash, ir, componentStates, inflight: AbortToken[], focusHint }` |
| 状态序列化 | 组件按 manifest 注册 serializer；单项预算 8 KB、总计 64 KB，超限 → 该项降级为"不保存"并标记 |
| 缓冲 | 内存环形缓冲 N=20；持久化快照（IndexedDB/加密）P2 再做 |
| 进行中请求 | 应用编排产生的请求经 Session 注册 AbortToken，回滚即取消；未注册的存量请求不承诺取消 |
| 回滚执行序 | 取消 inflight → 暂停摄入 → 恢复 IR → 重水化状态 → 恢复焦点 → 恢复摄入（会话锁保证原子性） |
| 重水化失败 | **降级不报错**：按旧 IR 全新渲染 + 提示"已恢复布局，部分输入未保留"。回滚机制自身不能成为新的故障源 |
| 防投毒 | 快照 IR 带 specHash，恢复时校验，不匹配即丢弃该快照 |

## 8. 遥测与指标

### 8.1 事件模型

| 事件 | 内容 | 默认 |
|---|---|---|
| verdict | ruleId/severity/action/计数 | 开（**不含 spec 内容**） |
| userAction | rollback/lock/confirm/revert + zoneId | 开 |
| perf | 各阶段耗时（10% 采样） | 开 |
| contentShape | props 的类型形状指纹（无值） | 关（opt-in） |

本地窗口聚合（30s 或 100 条批量上报），导出走 OTLP 或自定义端点；离线有界磁盘队列（1 MB），溢出丢最旧并计数。用户 ID 仅以**按组织加盐哈希**出现。opt-out 时完全本地化，指标仅保留在本地控制台。

### 8.2 第一代指标（精确定义，防口径漂移）

```
回滚率       = rollbackCount / appliedCount          （按 zone，7 天滑窗）
锁定率       = lockedZones / mutableZones
gate 拦截率   = blockedFrames / committedFrames
自动修复率   = transformedFrames / committedFrames
预估→实际差  = shadow 期预估拦截率 vs 实际拦截率（校准 Enforcement Ratchet）
```

反 gaming 原则：所有指标度量**用户可观测结果**（用户实际按了回滚/锁定），不采信 Agent 自评。

## 9. 审计链（企业版核心）

- **记录**：`{ seq, ts, specHash, policyHash, catalogHash, engineVersion, verdictDigest, userActionDigest }`，append-only，逐条哈希链（含前条哈希）；specHash 用按租户加盐哈希，防跨租户彩虹比对；
- **双跑验证（本产品的信任制高点）**：服务端取同版本四元组，对同一 spec 在 Node 端复算 Gate，verdictDigest 必须一致——把"客户端是否真的执行了治理"从口头声明变成可验证命题。可行性完全建立在 §3.3 确定性纪律上；
- **GDPR 冲突处理**：哈希链只存假名化摘要；可选明细 blob 按用户密钥加密，删除密钥即等效擦除。**此项需法务出具 DPIA 意见**，列入 P2 出口条件（§14）；
- 导出：签名 JSONL bundle + manifest，对接企业 SIEM。

## 10. 威胁模型（按信任边界展开）

| # | 威胁 | 缓解 |
|---|---|---|
| T1 | **UI 钓鱼/界面仿冒**（prompt injection 让 Agent 生成假登录/支付表单） | 敏感组件（Password/OTP/Payment）只允许出现在**构建期注册的安全 zone**（Agent 不可写 zone 注册表）；系统样式组件（对话框、权限请求样式）白名单；critical 级阻止 + 事件上报 |
| T2 | 数据外带（bindings 引到任意远端） | BindingRef 只能引用宿主注册的会话级数据源；组件 manifest 之外不出现 URL 类 prop |
| T3 | 规格洪水 DoS | §3.5 硬上限 + 隔离 + 帧背压 + resync 协议 |
| T4 | Gate 被当攻击面 | 规则是数据非代码；具名 fixer；有界匹配；显式栈遍历 |
| T5 | 解析差异 / 原型污染 | 显式构造器逐字段复制；Canonical JSON 后哈希；禁深合并 |
| T6 | 快照投毒 / 回滚滥用 | specHash 校验；locked zone 无视提案 |

## 11. 失败矩阵与 SLO

| 模块 | 失败 | 行为 | 观测 |
|---|---|---|---|
| adapter | 流损坏/截断 | 隔离当前帧 + fallback + resync | quarantine 计数 |
| gate | 任何异常 | GateGuard fail-closed + fallback | 完整 spec 转储（脱敏） |
| policy 编译 | 错误/放宽尝试 | **拒绝创建 Session**（fail-closed，属开发期错误） | 编译诊断 |
| catalog | 缺组件/版本不匹配 | block + 提示 | 缺失清单 |
| telemetry | 上报失败 | 有界队列降级，丢最旧 | drop 计数 |
| snapshot | 重水化失败 | 降级全新渲染 + 用户提示 | degrade 事件 |
| storage | 不可用 | 仅内存模式 | 启动事件标记 |

## 12. 测试与验证策略

- **性质测试（property-based）**：幂等性 `gate(gate(x).ir) ≡ gate(x)`；transform 单调性；跨平台确定性（同一 fixture 在 Node/Chromium/WebKit 跑出相同 trace 哈希——CI 矩阵强制）；
- **语料库回放**：录制真实 Agent 流 100+ fixtures 作为黄金语料，adapter 变更、策略变更、引擎变更全部要过回放 diff；
- **Adapter 一致性套件**：对损坏流做模糊测试（截断、交错、超长、循环引用、重复 ID），新协议接入必须先过套件；
- **策略回归**：见 §4.4，verdict digest diff 挡合并；
- **性能回归**：§3.6 预算即 CI 门禁，bench 用固定种子数据；
- **a11y 抽样**：生成 UI 的人工 WCAG 审计抽样作为第二代指标，每季度校准静态检查的召回率。

## 14. 交付路线与出口标准

| 阶段 | 范围 | 出口标准（不达标不进入下一阶段） |
|---|---|---|

## 15. 开放问题（需要显式决策，不留隐性假设）

1. **渲染后 a11y**：动态背景对比度、真实重叠不可静态分析。候选：dev-time axe 钩子（带外告警，不进 Gate）/ 仅承诺布局模板级保证。倾向后者 + 文档明示能力边界，P2 决策；
2. **MCP Apps 治理**：iframe 内容渲染期不可治理。候选：代理拆包 vs 明确 out-of-scope。倾向 out-of-scope（治理定位本就不依赖吞下所有协议），在对比文档中明示；
3. **WASM 化**：仅当 bench 证明 TS 不达预算时启用，不预先复杂化；
4. **多表面偏好同步**：同用户跨设备冲突（LWW + 锁定优先）推 P3；
5. **ChatKit adapter**：等其公开组件面稳定，避免对封闭生态做脆弱适配。
