# 开发指南（技术文档）

> 本文是仓库级技术约定：工具链、代码规范、**深度测试策略**、提交规范。
> 工程规格的"为什么"见 `产品设计v2-修订.md`；本文只写"怎么做"。

---

## 1. 技术栈

| 项 | 选择 | 备注 |
|---|---|---|
| 语言 | TypeScript（`strict: true`） | — |
| 运行时 | Node ≥ 20（开发/测试），现代浏览器（目标） | 核心包禁 Node/DOM API |
| 包管理 | pnpm v11 workspace | 见踩坑 PIT-002 |
| 模块 | ESM-only（KAN-002） | — |
| 测试 | vitest + fast-check（属性测试） | 覆盖率 v8 provider |
| CI | GitHub Actions | `.github/workflows/ci.yml` |

## 2. 仓库布局与依赖规则

```
packages/
  ir/     @genui/ir     零运行时依赖，无 DOM/Node API
  gate/   @genui/gate   零运行时依赖；只依赖 ir
  （后续）adapter-a2ui / audit / policy / session / gate-react / catalog / proposer-example
```

**依赖规则（评审纪律，KAN-005）**：
- `ir`、`gate` 的 `package.json` **不得出现 dependencies 字段**（devDependencies 不限）；
- `gate` 只 import `@genui/ir`；
- 代码中禁止 `Date.now()` / `Math.random()` / locale 相关比较（确定性纪律，v2 §6.3）；
- 集合遍历用稳定序；核心禁递归遍历树（显式栈，v2 §6.6）。

## 3. 深度测试策略

### 3.1 分层（每类库按适用性全覆盖）

| 层 | 工具/方法 | 硬性要求 |
|---|---|---|
| 单元测试 | vitest | 每个公开函数：正常、边界、拒绝路径 |
| **属性测试** | fast-check | 纯函数必须有：确定性（同输入同输出）、幂等/不动点、往返（round-trip）性质；每性质 ≥ 100 次随机用例（CI 全量跑） |
| **黄金向量** | 固定 fixtures | sha256 用 NIST 标准向量；canonical JSON 用手工金标样例（含嵌套/排序/转义/-0） |
| **交叉验证** | 与平台参照实现对拍 | 纯 TS sha256 ↔ `node:crypto`（仅测试文件可 import Node API）；随机字符串 ≥ 1000 组对拍 |
| **确定性测试** | 多次运行断言 | hash/canonicalize 跑两遍必须逐字节相等 |
| 回归语料 | 黄金语料库 | M1 建立录制语料；任何引擎/策略变更过回放 diff |
| 性能基准 | bench 脚本 | M0 后期接入 CI 预算门禁（v2 §6.6） |

### 3.2 门禁（每次提交前）

```powershell
pnpm test        # vitest run，全绿
pnpm typecheck   # tsc --noEmit，全绿
```

两者任一不红即禁止提交；CI 重复同样两步 + 覆盖率。

### 3.3 覆盖率要求

- 核心包（ir/gate）：statements / branches **≥ 90%**；
- 覆盖率不达标视为任务未完成，不允许"以后补测试"。

### 3.4 测试代码纪律

- 测试文件放 `test/`（与 `src/` 平级），命名 `*.test.ts`；
- 测试**可以**用 Node API（`node:crypto`、`node:fs`），但只能在 `test/` 内——核心保持环境无关；
- 每个属性测试必须带 `seed` 可复现注记（fast-check 失败输出自带 seed，贴进 issue）。

## 4. 代码规范

- TS `strict`；公开 API 显式类型；禁 `any`（测试代码放宽）；
- 导出只经各包 `src/index.ts`（公共 API 单一入口，1.0 稳定承诺的范围）；
- 错误处理：核心纯函数**不抛异常给调用方**——非法输入经校验器返回结构化错误（Gate/IR 的约定）；内部不变量被破坏时抛带错误码的 `Error` 子类（理论不可达，测试断言不可达）；
- 命名：文件 kebab-case，类型 PascalCase，函数 camelCase；规则 ID `kebab-case` 字符串。

## 5. 提交规范（小步提交）

- 格式：`feat|fix|docs|test|chore|refactor(scope): 描述`（中英文描述均可，语义清楚优先）；
- **一个提交 = 一个可独立回滚的语义单元**：实现与它的测试同提交；docs 与代码同提交优先；
- 每次提交前 §3.2 门禁全绿；
- 每次提交后回填 `进度.md` §3 提交日志。

## 6. 分支策略（0.x 期）

- 单主干 `master` 直接小步提交（solo 阶段最优）；
- 出现外部贡献者后再引入 `main` + PR 流程（记录于进度文档，不预先复杂化）。
